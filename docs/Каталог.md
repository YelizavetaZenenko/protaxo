# Каталог (Catalog_Item)

Довідник товарів і послуг. Пакет `com.example.protaxo.catalog`, URL `/catalog-items`, `/api/catalog-items`.

## Список: розділено на вкладки "Товари" / "Послуги"

За проханням користувача список більше не показує обидва типи однією таблицею з колонкою "Тип" — тепер два окремі під-вкладки (`.doc-tabs`/`.doc-tab-btn`, як в [[Наряд-заказ|Наряд-заказі]], тільки як звичайні посилання `<a>`, а не JS-перемикачі, бо це два різні GET-запити, не приховані панелі на одній сторінці):

- `GET /catalog-items?activeType=MATERIAL` — "Товари" (типове значення за замовчуванням, якщо параметр не передано)
- `GET /catalog-items?activeType=SERVICE` — "Послуги"

Фільтрація за типом — у контролері (`CatalogItemPageController.list`, просте `stream().filter(...)`), колонка "Тип" у таблиці прибрана як зайва (тип уже видно з того, яка вкладка активна). Кнопка "+ Нова позиція" й посилання "Скасувати" на формі несуть `activeType` через query-параметр, тому створення/редагування/скасування завжди повертає на ту вкладку, з якої почали (`CatalogItemFormData.type` — те саме поле форми, використане і для передзаповнення типу, і для побудови URL повернення: `th:href="@{/catalog-items(activeType=${catalogItem.type})}"`).

## Поля

- `type` — enum `CatalogItemType { SERVICE, MATERIAL }`
- `name`
- `basePrice` — базова ціна (використовується як підказка при виборі в [[Наряд-заказ|Наряд-заказі]], користувач може її змінити на конкретному документі)
- `stockQuantity` — залишок на складі, **лише інформаційний**, нічого його не зменшує (див. [[Що ще зробити]]). **Тип `Integer`, лише ціле невід'ємне число** (до 2026-09-07 був `BigDecimal` з 3 знаками після коми — змінено за проханням користувачки, `V28__catalog_stock_quantity_integer.sql`, існуючі значення вже були цілими, тому каст безпечний). Для `type = SERVICE` поле **завжди `null`** — див. нижче

## Залишок недоступний для послуг (2026-09-07)

Раніше поле "Залишок на складі" на формі `/catalog-items/new`/`/catalog-items/{id}/edit` було просто підписане текстовою підказкою "Залиште порожнім для послуг" — нічого не заважало фактично ввести число для позиції типу `SERVICE`. За проханням користувачки тепер це **автоматично блокується**, не лише підказується:

- **UI**: JS (`catalog-items/form.html`) на `change` селекта "Тип" (і одразу на завантаженні сторінки) вимикає (`disabled`) поле "Залишок" і очищує його значення, коли обрано `SERVICE`; підказка під полем змінена на "Недоступно для послуг". Вимкнений (`disabled`) інпут браузер не відправляє при сабміті форми, тому бекенд отримує `null`, а не `0`
- **Сервер**: `CatalogItemService.clearStockForServices()` викликається в кінці і `create()`, і `update()` — примусово виставляє `stockQuantity = null` для будь-якого `CatalogItem` з `type = SERVICE`, **незалежно** від того, що прийшло в запиті (захист не лише на рівні UI, той самий підхід, що вже застосовувався для `internalNumber` у [[Протокол калібрування (CalibrationProtocol)]] — пряме підроблене API-звернення теж не зможе виставити залишок послузі)

**Формат — лише ціле число**: JS-фільтр на `input` прибирає все, крім цифр (`replace(/\D/g, '')`), той самий підхід, що для `code` контрагента; HTML `type="number" step="1"`; серверна валідація — `@Min(0)` на `Integer` (не `BigDecimal`, тип поля змінено — див. вище).

## Послуги калібрування (зв'язок з протоколом)

Три позиції типу `SERVICE`, засіяні міграцією `V24__add_calibration_service_catalog_items.sql`: "Калібрування тахографа-Аналоговий", "-Цифровий", "-Smart" (по 800/800/900 грн — орієнтовна базова ціна, можна поправити прямо в UI каталогу). Наявність будь-якої з них серед позицій наряд-заказу вмикає кнопку "Створити протокол" на сторінці перегляду — перевірка йде за **префіксом назви** (`itemName.startsWith("Калібрування тахографа")`), не за жорстко зашитим id, див. [[Протокол калібрування (CalibrationProtocol)]]. Якщо перейменувати ці позиції так, що вони перестануть починатись з цього префіксу, — кнопка перестане з'являтись.

## Сортування, пошук і перегляд по кліку (2026-09-14)

- **Сортування за ID** — `catalogItemRepository.findAllByOrderByIdAsc()` замість неупорядкованого `findAll()` (список раніше показувався у випадковому порядку вставки в БД).
- **Пошук за назвою** — `?filterName=` (`CatalogItemPageController.list`, той самий підхід, що фільтр за назвою/ЄДРПОУ в [[Контрагенти]]: `stream().filter(containsIgnoreCase(...))`, не запит до БД). Поле пошуку **скидається** при перемиканні вкладки "Товари"/"Послуги" (посилання вкладок навмисно **не** несуть `filterName` в query — свідомий вибір за проханням користувача, на відміну від `activeType`, який завжди зберігається).
- **Перегляд по кліку на рядок** — `GET /catalog-items/{id}` (`catalog-items/view.html`), той самий патерн `clickable-row` + `data-href`, що в інших списках. Тип показується українською ("Товар"/"Послуга") прямо в шаблоні через `${catalogItem.type.name() == 'MATERIAL'} ? 'Товар' : 'Послуга'` — **весь тернарний вираз цілком усередині одного `${...}`**, той самий підхід, що вирішує пастку нижче. "Залишок" показується лише для товарів (`th:if`).
- Той самий переклад типу (Товар/Послуга) додано і в `<select>` на формі створення/редагування — раніше показувались сирі назви enum (`MATERIAL`/`SERVICE`), значення `<option>` лишились ті самі enum-рядки, змінився лише видимий текст.

## Підключено лише до Наряд-заказу

За явним рішенням користувача — НЕ підключено до модуля "Наряди" (Order), хоча в оригінальній специфікації `OrderItem` мав посилатись саме на `Catalog_Item`. Модуль "Наряди" згодом повністю видалений з системи — деталі обох рішень [[Рішення і відхилення]].

## Відома пастка при розробці (історична, з часів єдиної таблиці з колонкою "Тип")

Спроба показати тип позиції українською через тернарний вираз у Thymeleaf:
```
(${ci.type} == T(...).SERVICE ? 'Послуга' : 'Матеріал') + ': ' + ${ci.name}
```
**не парситься** Thymeleaf (`TemplateProcessingException`, сторінка падає з `500`) — увесь вираз має бути **цілком** усередині одного `${...}` (див. той самий клас пасток у [[Тестування]]). Колонку "Тип" відтоді прибрано зовсім (див. вище, розділення на вкладки), тому цей конкретний рядок коду більше не існує — лишено як загальний урок на майбутнє.
