# Каталог (Catalog_Item)

Довідник товарів і послуг. Пакет `com.example.protaxo.catalog`, URL `/catalog-items`, `/api/catalog-items`.

## Список: розділено на вкладки "Товари" / "Послуги"

За проханням користувача список більше не показує обидва типи однією таблицею з колонкою "Тип" — тепер два окремі під-вкладки (`.doc-tabs`/`.doc-tab-btn`, як в [[Наряд-заказ|Наряд-заказі]], тільки як звичайні посилання `<a>`, а не JS-перемикачі, бо це два різні GET-запити, не приховані панелі на одній сторінці):

- `GET /catalog-items?activeType=MATERIAL` — "Товари" (типове значення за замовчуванням, якщо параметр не передано)
- `GET /catalog-items?activeType=SERVICE` — "Послуги"

Фільтрація за типом — у контролері (`CatalogItemPageController.list`, просте `stream().filter(...)`), колонка "Тип" у таблиці прибрана як зайва (тип уже видно з того, яка вкладка активна). Кнопка "+ Нова позиція" й посилання "Скасувати" на формі несуть `activeType` через query-параметр, тому створення/редагування/скасування завжди повертає на ту вкладку, з якої почали (`CatalogItemFormData.type` — те саме поле форми, використане і для передзаповнення типу, і для побудови URL повернення: `th:href="@{/catalog-items(activeType=${catalogItem.type})}"`).

## Поля

- `type` — enum `CatalogItemType { SERVICE, MATERIAL }`
- `name`
- `basePrice` — базова ціна (використовується як підказка при виборі в [[Наряд-заказ|Наряд-заказі]], користувач може її змінити на конкретному документі)
- `stockQuantity` — залишок на складі, **лише інформаційний**, нічого його не зменшує (див. [[Що ще зробити]])

## Послуги калібрування (зв'язок з протоколом)

Три позиції типу `SERVICE`, засіяні міграцією `V24__add_calibration_service_catalog_items.sql`: "Калібрування тахографа-Аналоговий", "-Цифровий", "-Smart" (по 800/800/900 грн — орієнтовна базова ціна, можна поправити прямо в UI каталогу). Наявність будь-якої з них серед позицій наряд-заказу вмикає кнопку "Створити протокол" на сторінці перегляду — перевірка йде за **префіксом назви** (`itemName.startsWith("Калібрування тахографа")`), не за жорстко зашитим id, див. [[Протокол калібрування (CalibrationProtocol)]]. Якщо перейменувати ці позиції так, що вони перестануть починатись з цього префіксу, — кнопка перестане з'являтись.

## Підключено лише до Наряд-заказу

За явним рішенням користувача — НЕ підключено до модуля "Наряди" (Order), хоча в оригінальній специфікації `OrderItem` мав посилатись саме на `Catalog_Item`. Модуль "Наряди" згодом повністю видалений з системи — деталі обох рішень [[Рішення і відхилення]].

## Відома пастка при розробці (історична, з часів єдиної таблиці з колонкою "Тип")

Спроба показати тип позиції українською через тернарний вираз у Thymeleaf:
```
(${ci.type} == T(...).SERVICE ? 'Послуга' : 'Матеріал') + ': ' + ${ci.name}
```
**не парситься** Thymeleaf (`TemplateProcessingException`, сторінка падає з `500`) — увесь вираз має бути **цілком** усередині одного `${...}` (див. той самий клас пасток у [[Тестування]]). Колонку "Тип" відтоді прибрано зовсім (див. вище, розділення на вкладки), тому цей конкретний рядок коду більше не існує — лишено як загальний урок на майбутнє.
