# Технологічний стек

## Бекенд

- **Java 21**, **Spring Boot 4.1.0** (не 3.x, як зазначено в оригінальній специфікації — див. [[Рішення і відхилення]])
- **Spring Data JPA / Hibernate 7.4.1** — soft delete (`deletedAt`) + auditing (`createdAt`/`updatedAt`) через `BaseEntity` і `@EnableJpaAuditing`; `@SQLRestriction` для фільтрації видалених записів; `@Version` для оптимістичних блокувань, `@Lock(PESSIMISTIC_WRITE)` — для рідкісних місць, де потрібне реальне блокування рядків (напр. перевірка "останній адміністратор", [[Безпека і ролі]])
- **Spring Security** — сесійна автентифікація для сайту + HTTP Basic для API, кастомний `AuthorizationManager` для динамічних (з БД) прав через `RolePermissions`, `BCryptPasswordEncoder` для паролів (див. [[Безпека і ролі]])
- **Spring WebSocket** (`spring-boot-starter-websocket`) — канал `/ws/print-agent` для [[Print Agent]], токен-автентифікація на handshake, `@Scheduled` (`@EnableScheduling`) ping/pong-моніторинг живості з'єднань
- **Thymeleaf** — серверний рендеринг сторінок, `thymeleaf-extras-springsecurity6` для `sec:authorize` у шаблонах; окремий `SpringTemplateEngine` у `TemplateMode.XML` для PDF-шаблонів (див. [[PDF-генерація]])
- **MapStruct 1.6.3** + **Lombok** — мапери Entity ↔ DTO, зменшення шаблонного коду
- **Jackson (Spring Boot 4 / Jackson 3)** — серіалізація JSON, пакет тепер `tools.jackson.*`, не `com.fasterxml.jackson.*` (лишився на старому груп-ID тільки `jackson-annotations`) — пастка, знайдена на фічі `RolePermissions`
- **ZXing** (`com.google.zxing:core`) — генерація PNG-зображення QR-коду лише для HTML-прев'ю наклейки (`/calibration-protocols/{id}/label-preview`); на реальному друку QR малює сам термопринтер командою TSPL `QRCODE`, ZXing там не бере участі

## База даних

- **PostgreSQL 16** (Docker, продакшн) / **17** (нативний інстальований локально на машині розробки) — база `protaxo`
- **Flyway** — усі зміни схеми лише через міграції (`src/main/resources/db/migration`), Hibernate працює в режимі `ddl-auto=validate` і нічого сам не створює. `flyway-core` + окрема `spring-boot-flyway` (без якої в Spring Boot 4 міграції мовчки не запускаються) + `flyway-database-postgresql`
- `TIMESTAMPTZ` для всіх `Instant`-колонок + `ALTER DATABASE ... SET timezone` (Europe/Kyiv) — виправлення бага з часом, див. [[База даних]]

## Веб-шар / фронтенд

- Мінімальний власний CSS (`static/css/style.css`), без сторонніх фреймворків і CDN — Google Fonts (`Golos Text` для тексту, `Unbounded` для логотипу) підключені через `@import` у самому CSS
- Vanilla JS для інтерактивних елементів (комбобокси, чернетки наряд-заказу/протоколу в `localStorage`, модальні вікна дат) — без React/Vue/jQuery, свідоме відхилення від React в оригінальній специфікації, див. [[Рішення і відхилення]]

## Друк наклейок — [[Print Agent]]

- **Окремий легкий Java-процес** (`print-agent/`, той самий Java 21, без Spring — щоб не тягнути важкий рантайм на комп'ютер СТО), під'єднується по WebSocket до бекенду
- **`java.net.http.WebSocket`** (вбудований у JDK, без сторонньої бібліотеки) — клієнтський WebSocket, включно з автоматичною відповіддю на `Ping`-фрейми сервера стандартним протокольним механізмом (жодного власного коду для цього не знадобилось)
- **TSPL2** — рідна командна мова принтерів TSC; наклейки калібрування генеруються як сирі TSPL2-команди (`TsplLabelBuilder`), включно з растровим логотипом через команду `BITMAP` (`TsplBitmap` — власна конвертація `BufferedImage` в 1-біт-на-піксель формат)
- **`javax.print`** — надсилання сирих TSPL-байтів на системний принтер Windows ("raw passthrough", без GDI-рендерингу)
- **Windows-1251** — кодування кириличних `TEXT`-команд для друку (сам протокол TSPL передбачає кодову сторінку, не Unicode)

## Інфраструктура та розгортання — [[Варіанти розгортання (сервер)]]

- **Docker** + **Docker Compose** — production-стек із трьох контейнерів (`app`, `postgres`, `caddy`) в одній ізольованій мережі, multi-stage `Dockerfile` (jarmode `tools`, Spring Boot 4 перейменування колишнього `layertools`)
- **Contabo Cloud VPS** (Hub Europe) — хмарний сервер, обраний після порівняння з Hetzner/Kamatera/netcup
- **Tailscale VPN** — приватний доступ до всієї системи, MagicDNS (`*.ts.net`), справжній Let's Encrypt-сертифікат через `tailscale cert` (не самопідписаний)
- **Tailscale Funnel** (2026-09-21) — точкове виключення з приватності: єдиний публічний вхід `/verify/*` для сканування QR калібрувального протоколу сторонніми людьми без Tailscale, на окремому порту (8443), решта системи лишається недосяжною ззовні. Детальніше — [[Print Agent#Баг: "публічний" маршрут насправді був недосяжний для реальних сторонніх людей (знайдено й виправлено 2026-09-21)]]
- **Caddy** — реверс-проксі й термінація TLS для основного сайту; окремий вузький HTTP-вхід (`:8081`, лише `/verify/*`) для Tailscale Funnel
- **cron** (Linux, сервер) — щоденний бекап-скрипт бази (`scripts/backup-db.sh`, bash-порт `backup-db.ps1`)
- **Windows Task Scheduler** + **PowerShell** (`scripts/pull-remote-backups.ps1`) — офсайт-копіювання бекапів на комп'ютер адміністраторки через Tailscale/`scp`

## Особливість Spring Boot 4

Autoconfigure розбитий на дрібні модулі. Flyway сам по собі (`flyway-core`) більше не тягне автоконфігурацію — потрібна ще окрема залежність `org.springframework.boot:spring-boot-flyway`. Без неї міграції просто не запускаються без жодної помилки в консолі (виглядає, ніби Flyway працює, але таблиці не створюються).

## Архітектура коду

Вертикальні зрізи по модулях (не по шарах): кожен модуль (`client`, `vehicle`, `invoice`, `catalog`, `security`, `calibration`, `printagent`...) має свої `entity/ dto/ mapper/ repository/ service/ controller/ web/`. Контролери діляться на:
- REST (`*Controller`, `/api/...`) — повертають DTO, для Postman/зовнішніх інтеграцій
- Web (`*PageController`, без префіксу `/api`) — рендерять Thymeleaf-сторінки, використовують ті самі Service

Див. [[Запуск проєкту]] для інструкцій зі старту.
