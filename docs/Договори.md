# Договори (Contract)

Договір з [[Контрагенти|контрагентом]]. Пакет `com.example.protaxo.contract`, URL `/contracts`, `/api/contracts`.

## Поля

- `clientId` — FK на [[Контрагенти]] (єдине поле, яке вводиться вручну)
- `contractNumber` — **проставляється автоматично** при створенні, у форму не вводиться (як `Invoice.number`) — джерело: окрема Postgres-послідовність `contract_number_seq`, формат `%06d`. Номер не змінюється при редагуванні договору
- ~~`status`~~ — **прибрано повністю** (2026-09-07, за проханням користувачки) — жодного enum'у, жодної колонки в БД (`V29__contract_auto_number_no_status.sql`, `ALTER TABLE contracts DROP COLUMN status`). Немає стану "призупинено"/"розірвано" — кожен договір у системі вважається чинним за визначенням, доки існує (soft delete прибирає його зі списку так само, як і будь-де в проєкті)

## Форма `/contracts/new` / `/contracts/{id}/edit`

Після прибирання номера й статусу лишилось єдине поле — "Контрагент" (випадаючий список). "Номер договору" показується як текст, лише для читання (той самий патерн, що "Номер"/"Дата та час" на формі [[Наряд-заказ|Наряд-заказу]]): `"буде проставлено автоматично при збереженні"`, доки не збережено, реальний номер — після.

## Список

`GET /contracts` — таблиця ID / Контрагент / Номер договору, без фільтрів і без колонки "Статус" (прибрана разом з полем). Перенесено на спільний клас `.clean-table` (був звичайний `<table>` без стилю).

## Перегляд по кліку на рядок (2026-09-14)

`GET /contracts/{id}` (`contracts/view.html`) — раніше договори мали лише список і форму (без окремої сторінки перегляду, на відміну від [[Автомобілі]]/[[Контрагенти]]); тепер клік по рядку в `/contracts` відкриває read-only сторінку з контрагентом і номером договору. Той самий `clickable-row`/`data-href`-патерн, що всюди в проєкті.

## Автопідстановка в "Рахунок на оплату" (2026-09-07)

Рядок "Договір:" на PDF [[Наряд-заказ#"Рахунок на оплату" — окремий PDF-документ (не те саме, що PDF наряд-заказу)|"Рахунок на оплату"]] раніше завжди був порожньою підкресленою лінією для ручного дописування. Тепер `InvoicePageController.printBillPdf` підтягує **останній договір контрагента** цього наряд-заказу (`ContractService.findLatestByClientId`, `ContractRepository.findFirstByClient_IdOrderByIdDesc` — найбільший `id`, тобто найновіше створений) і виводить його `contractNumber` у шаблон.

- Якщо в контрагента **є** хоча б один договір — рядок показує реальний номер: `№ 000002`
- Якщо договорів **немає** — лишається стара поведінка, порожня лінія (`.fill-line`) для ручного дописування — жодної помилки чи "N/A", просто той самий вигляд, що й раніше
- **Не FK-зв'язок** між `Invoice` і `Contract` — зіставлення виключно за `clientId`, той самий підхід, що вже використовується для "дати останнього візиту" автомобіля в [[Наряд-заказ]]. Якщо в контрагента кілька договорів, у рахунок завжди підставляється найновіший (за `id`) — вибір "останнього" як найбільш імовірно чинного, без окремого поля для позначення "головного" договору

## Використовується в

Раніше — модулем "Наряди" (Order, `contractId` опційний FK). Той модуль **повністю видалений** — див. [[Рішення і відхилення]]. Сам "Наряд-заказ" теж не має прямого FK на договір — лише непряме зіставлення за контрагентом для рахунку (див. вище). Договори лишаються самостійним довідником.
