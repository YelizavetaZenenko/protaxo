# Договори (Contract)

Договір з [[Контрагенти|контрагентом]]. Пакет `com.example.protaxo.contract`, URL `/contracts`, `/api/contracts`.

## Поля

- `clientId` — FK на [[Контрагенти]] (єдине поле, яке вводиться вручну)
- `contractNumber` — **проставляється автоматично** при створенні, у форму не вводиться (як `Invoice.number`) — джерело: окрема Postgres-послідовність `contract_number_seq`, формат `%06d`. Номер не змінюється при редагуванні договору
- ~~`status`~~ — **прибрано повністю** (2026-09-07, за проханням користувачки) — жодного enum'у, жодної колонки в БД (`V29__contract_auto_number_no_status.sql`, `ALTER TABLE contracts DROP COLUMN status`). Немає стану "призупинено"/"розірвано" — кожен договір у системі вважається чинним за визначенням, доки існує (soft delete прибирає його зі списку так само, як і будь-де в проєкті)

## Форма `/contracts/new` / `/contracts/{id}/edit`

Після прибирання номера й статусу лишилось єдине поле — "Контрагент" (випадаючий список). "Номер договору" показується як текст, лише для читання (той самий патерн, що "Номер"/"Дата та час" на формі [[Наряд-заказ|Наряд-заказу]]): `"буде проставлено автоматично при збереженні"`, доки не збережено, реальний номер — після.

## Список

`GET /contracts` — таблиця Номер договору / Контрагент, без фільтрів і без колонки "Статус" (прибрана разом з полем). Перенесено на спільний клас `.clean-table` (був звичайний `<table>` без стилю).

**Колонка "ID" прибрана, "Номер договору" винесено першою (2026-09-20)** — за проханням користувачки: `id` не ніс жодної корисної інформації для користувача (внутрішній технічний ключ), а номер договору — це і є той ідентифікатор, за яким документ шукають/впізнають. Заголовок колонки лишився текстом "Номер договору", без символу "№" — сам номер (`contractNumber`, наприклад `"000003"`) і так очевидно є числом за контекстом заголовка, додатковий символ "№" був би зайвим.

## Перегляд по кліку на рядок (2026-09-14)

`GET /contracts/{id}` (`contracts/view.html`) — раніше договори мали лише список і форму (без окремої сторінки перегляду, на відміну від [[Автомобілі]]/[[Контрагенти]]); тепер клік по рядку в `/contracts` відкриває read-only сторінку з контрагентом і номером договору. Той самий `clickable-row`/`data-href`-патерн, що всюди в проєкті.

## Автопідстановка в "Рахунок на оплату" (2026-09-07)

Рядок "Договір:" на PDF [[Наряд-заказ#"Рахунок на оплату" — окремий PDF-документ (не те саме, що PDF наряд-заказу)|"Рахунок на оплату"]] раніше завжди був порожньою підкресленою лінією для ручного дописування. Тепер `InvoicePageController.printBillPdf` підтягує **останній договір контрагента** цього наряд-заказу (`ContractService.findLatestByClientId`, `ContractRepository.findFirstByClient_IdOrderByIdDesc` — найбільший `id`, тобто найновіше створений) і виводить його `contractNumber` у шаблон.

- Якщо в контрагента **є** хоча б один договір — рядок показує реальний номер: `№ 000002`
- Якщо договорів **немає** — лишається стара поведінка, порожня лінія (`.fill-line`) для ручного дописування — жодної помилки чи "N/A", просто той самий вигляд, що й раніше
- **Не FK-зв'язок** між `Invoice` і `Contract` — зіставлення виключно за `clientId`, той самий підхід, що вже використовується для "дати останнього візиту" автомобіля в [[Наряд-заказ]]. Якщо в контрагента кілька договорів, у рахунок завжди підставляється найновіший (за `id`) — вибір "останнього" як найбільш імовірно чинного, без окремого поля для позначення "головного" договору

## PDF самого договору (2026-09-17)

`GET /contracts/{id}/pdf` (`ContractPageController.printPdf`, шаблон `templates/pdf/contract.html`) — кнопка "Договір PDF" у списку й на сторінці перегляду. Повний текст типового договору поставки обладнання/техобслуговування/ремонту ТЗ (19 пронумерованих розділів — предмет, приймання ТЗ, порядок виконання робіт, гарантія, форс-мажор тощо) — узятий з нотатки [[Договір]] у цьому vault, дослівно, лише зі стилізацією в HTML.

- **Джерело тексту було пошкоджене** — файл [[Договір]] прийшов з побитим OCR/копіюванням: преамбула (сторони) і блок реквізитів/підписів мали дублікатний "сміттєвий" текст, що проривався з колонтитула (`"ПОСТАВКИ ОБЛАДНАННЯ, ТЕХНІЧНОГО ОБСЛУГ..."` вклинювалось усередині речень). Самі 19 пронумерованих розділів (предмет договору й далі) виявились **чистими**, без пошкоджень — перенесені дослівно. Преамбулу й реквізити реконструйовано за очевидною типовою структурою такого договору (мітка + порожня лінія для заповнення вручну там, де не було реальних даних).
- **Виконавець захардкоджений як `ФОП Вишивата Діана Олександрівна`** — та сама юридична особа й та сама адреса (`Україна, 11709, Житомирська обл., Звягельський р-н, місто Звягель, пров. Богуна, будинок 19-Б, квартира 2`), що вже використовується в [[Наряд-заказ#"Акт виконаних робіт" — окремий PDF-документ, стандартний вигляд без зразка (2026-09-16)|Акті]] і PDF [[Протокол калібрування (CalibrationProtocol)|Протоколу калібрування]]. У самому файлі [[Договір]] помилково стояло інше ім'я ("ФОП Линдюк Данило") — уточнено напряму в користувачки, яке ім'я реальне; використано узгоджене з рештою системи.
- **"Замовник" підтягується з реальних даних клієнта** (`ClientResponse`, той самий об'єкт, що й у [[Наряд-заказ#"Рахунок на оплату" — окремий PDF-документ (не те саме, що PDF наряд-заказу)|Рахунку]]) — найменування, ЄДРПОУ або РНОКПП (яке заповнене), телефон, email, контактна особа як "Керівник/представник". Поля без даних (адреса, IBAN, банк, ІПН ПДВ — таких стовпців немає в `Client`) лишаються порожньою підкресленою лінією для ручного дописування, той самий патерн, що в Рахунку.
- **Дата договору** — нове обчислюване поле `ContractResponse.contractDate` (`LocalDate`, мапиться з `Contract.createdAt` через вираз у `ContractMapper`, БЕЗ нової колонки в БД) — до цього моменту в договору взагалі не було жодного дато-поля в DTO.
- **Шрифт** — `'Times New Roman'` (Liberation Serif, як і в Рахунку/Наряд-заказі) — свідомий вибір для офіційного юридичного документа, без окремого прохання від користувачки (вона просила лише сам факт генерації PDF за цим текстом).
- **Розділи "⸻" з оригіналу замінено на `<h2>` з `border-top`** — сам символ "три-ем-дефіс" (U+2E3B) не чіпали навіть на пробу: та сама пастка з відсутнім гліфом у Liberation Serif, що вже задокументована в [[Наряд-заказ#"Рахунок на оплату" — окремий PDF-документ (не те саме, що PDF наряд-заказу)|Рахунку]] ("Технічна пастка (повторно актуальна)").

## Використовується в

Раніше — модулем "Наряди" (Order, `contractId` опційний FK). Той модуль **повністю видалений** — див. [[Рішення і відхилення]]. Сам "Наряд-заказ" теж не має прямого FK на договір — лише непряме зіставлення за контрагентом для рахунку (див. вище). Договори лишаються самостійним довідником.
