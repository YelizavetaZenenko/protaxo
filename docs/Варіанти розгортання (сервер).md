# Варіанти розгортання (сервер)

Обговорено 2026-09 — **рішення поки не прийняте**, тримаємо на майбутнє. Мета: система має працювати автономно (без потреби тримати робочий ПК увімкненим).

## Розглянуті варіанти

| Варіант | Плюси | Мінуси |
|---|---|---|
| **Raspberry Pi** | Найдешевший вхід, низьке споживання | ARM-архітектура (треба перевіряти сумісність), SD-картка ненадійна для БД — **обов'язково USB SSD**, а не SD |
| **Mini PC** (Intel NUC, Beelink тощо) | Звичайна x86-архітектура (як на десктопі, без ARM-нюансів), потужніший за RPi, теж компактний і дешевий (~$150–300) | Трохи дорожче за RPi |
| **NAS** (Synology, QNAP) | Поєднує сховище + Docker (Synology Container Manager) в одному пристрої, вбудовані бекапи "з коробки" | Дорожче (від ~$200 без дисків) |
| **Стара/запасна машина** | 0 грн на нове обладнання, потужніша за RPi | Більше споживання електрики, гучніша/більша |
| **Хмарний VPS** (Hetzner, DigitalOcean, Oracle Cloud free tier) | Не залежить від електрики/інтернету в офісі, простіше зробити HTTPS | Щомісячна оплата (крім Oracle free tier); дані фізично поза офісом — питання довіри для внутрішньої системи компанії |

## Орієнтовна рекомендація (не остаточне рішення)

- Якщо пріоритет — "поставив і забув" без ARM-клопоту: **Mini PC**
- Якщо треба надійне зберігання даних з бекапами "з коробки": **NAS**
- **Raspberry Pi** лишається найдешевшим входом, якщо не проти повозитись із USB SSD

Пов'язано: [[Запуск проєкту]] (поточний локальний Docker-based запуск), [[Безпека і ролі]] (зараз лише HTTP, не HTTPS — важливо, якщо колись відкривати доступ поза локальну мережу).
