# Водії (Driver)

Водій, прив'язаний до [[Контрагенти|контрагента]]. Пакет `com.example.protaxo.driver` не змінився, але **окремої вкладки/сторінки в UI більше немає** — за проханням користувача керування водіями повністю перенесено на сторінку перегляду контрагента (`GET /clients/{id}`), розділ "Водії". `DriverPageController` (сторінки `/drivers`, `/drivers/new`, `/drivers/{id}/edit`) і шаблони `drivers/list.html`/`drivers/form.html` **видалені**; `DriverFormData` теж видалено як більше не використовуваний.

## Поля

- `clientId` — FK на [[Контрагенти]]
- `fullName` — обов'язкове (`@NotBlank`)
- `phone` — **обов'язкове** й валідується форматом `^\+380\d{9}$` (`@NotBlank` + `@Pattern` у `DriverRequest`, за проханням користувачки — "рівно по скрипту, якщо цифр менше — не дозволяти зберігати"). Раніше було опційне без формату. Валідація на СЕРВЕРІ (тому діє для **всіх** місць, що створюють водія — і `clients/view.html`, і `clients/form.html`, і модалка "+ Додати нового водія" на формі [[Наряд-заказ]]), і продубльована на клієнті в `clients/view.html`/`clients/form.html` (та сама регулярка, показує помилку в модалці одразу, без звернення до сервера) — модалку на формі наряд-заказу клієнтською валідацією поки не оновлено, але серверна все одно не пропустить некоректний телефон звідти теж

## Де тепер живе UI

На `clients/view.html` — таблиця водіїв контрагента (`driverService.findByClientId(id)`, рендериться сервером при першому завантаженні сторінки) + кнопка "+ Додати водія" і кнопки "Редагувати"/"Видалити" в кожному рядку. Усе подальше керування (додавання, редагування, видалення) — **суто через `fetch` до вже наявного REST API**, без жодних нових серверних сторінок:

- **Додати** — модальне вікно (ПІБ і телефон обов'язкові, телефон звіряється з `^\+380\d{9}$` на клієнті перед відправкою) → `POST /api/drivers`
- **Редагувати** — те саме модальне вікно, попередньо заповнене з `data-*` атрибутів рядка → `PUT /api/drivers/{id}`
- **Видалити** — стилізована модалка підтвердження (`#confirmModalOverlay`, спільна функція `showConfirm(message, onConfirm)`) замість браузерного `confirm()` — за проханням користувачки ("підказка... повинна гарно виглядати, а не як зараз у вигляді вспливаючого вікна"); підтвердивши, викликає `DELETE /api/drivers/{id}` (ADMIN-only на рівні `SecurityConfig`, кнопка також схована через `sec:authorize` для не-ADMIN). `showConfirm` — невеликий переніспользуваний хелпер, продубльований в обох шаблонах (`clients/view.html`, `clients/form.html`), а не винесений у спільний файл — узгоджено зі стилем проєкту (кожна сторінка має власний inline `<script>`)

Жодних нових Java-контролерів для цього не знадобилось — `DriverController` (REST, `/api/drivers`) уже мав повний CRUD (`GET`/`POST`/`PUT`/`DELETE`) ще з часу, коли існувала стара сторінка `/drivers`; тепер той самий контролер обслуговує UI напряму з клієнтського JS.

## Використовується в

- `GET /api/clients/{clientId}/drivers` (`client.web.ClientLookupController`, метод `DriverService.findByClientId`) — підтягує водіїв обраного контрагента для випадаючого списку в полі "Водій" на вкладці "Наряд" у [[Наряд-заказ|Наряд-заказі]]. Це **не FK-зв'язок**: поле в Invoice лишається вільним текстом, лише джерело варіантів тепер звужене до реальних водіїв контрагента — див. [[Наряд-заказ]]
- `POST`/`PUT`/`DELETE /api/drivers` — тепер використовується і модальним вікном на сторінці [[Контрагенти|Контрагента]] (основний спосіб керування), і модальним вікном "+ Додати нового водія" прямо з форми наряд-заказу

Раніше також використовувався модулем "Наряди" (Order) — той модуль **повністю видалений**, див. [[Рішення і відхилення]].
